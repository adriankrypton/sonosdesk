# Desktop API (SonosDesk.Server ↔ Electron)

The Electron app (`electron/`) is the user interface on macOS (Apple Silicon and Intel) and Windows.
All Sonos, radio and receiver logic runs in `SonosDesk.Server`, a .NET process that the Electron main
process starts and stops. It reuses `SonosDesk.Core` and `SonosDesk.Infrastructure` unchanged.

## Start-up handshake

- Electron starts the server executable (`SonosDesk.Server`, or `dotnet run` in development) with the
  environment variables:
  - `SONOSDESK_TOKEN` – random 32-byte hex string generated by Electron for this run.
  - `SONOSDESK_SECRET_KEY` – base64 32-byte key, created once and kept with Electron `safeStorage`
    (Keychain on macOS, DPAPI on Windows). Used by the server to encrypt secrets (Control API tokens).
  - `SONOSDESK_DATA_DIR` – optional data folder (default: the platform's application data folder + `SonosDesk`).
  - `SONOSDESK_LANGUAGE` – optional UI language (`de`, `en`, …) for server-side messages.
- The server binds to `127.0.0.1` on a free port and writes exactly one line to stdout:
  `SONOSDESK_READY http://127.0.0.1:<port>`
- Every HTTP request needs the header `Authorization: Bearer <token>`. Image URLs and the WebSocket
  accept `?token=<token>` instead (an `<img>` cannot send headers). Requests with another `Host` than
  `127.0.0.1:<port>` are rejected (DNS rebinding protection).
- When stdin closes (Electron quits), the server stops.

## Conventions

- JSON, camelCase property names, enums as camelCase strings (`"playing"`, `"radio"`, `"repeatAll"` …).
- Errors: HTTP 4xx/5xx with `{ "message": "<localized text>", "kind": "<SonosErrorKind camelCase>" }`.
- Times are numbers in seconds. Volumes are integers 0–100.
- `artUrl` values are already API URLs (`/api/art?u=…`), relative to the server base; append `&token=`.

  "backend": "Lokal (UPnP)",
  "capabilities": ["playback", "seek", "queue", "soundSettings", "sleepTimer", "crossfade", "favorites", "playStreamUrl", "grouping", ...],

## Events

`GET /api/events?token=…` (WebSocket). Server → client messages `{ "type": …, "data": … }`:

| type | data |
| --- | --- |
| `snapshot` | full snapshot (after topology changes) |
| `group` | `GroupDto` (state of one group changed; arrives every few seconds while playing) |
| `discovery` | `DiscoveryDto` |
| `receiver` | `ReceiverDto` |
| `settings` | `AppSettings` |
| `notice` | `{ "severity": "info|success|warning|error", "message": "…" }` |

While at least one client is connected, the server polls the active group every 2 s and receivers every 3 s.

| --- | --- |
| `GET /api/radio/popular?country=DE` | → `[RadioStationDto]` |
